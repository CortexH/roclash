# BUG 001 — Torre atacando unit incorretamente

## Contexto

Existem:

- 2 units que atacam o "bolso do jogador";
- 1 unit de torre;
- 1 unit de parede longe do range de ataque da torre.

A situação inicial:

- Uma unit é spawnada próxima da parede.
- Outra unit é spawnada longe da parede.
- Essa segunda unit também está mais longe da torre, porém ainda dentro do alcance de aggro.
- A primeira unit consegue destruir a parede antes da segunda unit chegar nela.

---

## Passo a passo

1. Spawnar Unit A próxima da parede.

2. Spawnar Unit B:
   - mais longe da parede que a Unit A;
   - mais longe da torre que a Unit A;
   - porém ainda dentro do alcance de aggro da torre.

3. Unit A destrói a parede antes da Unit B chegar nela.

---

## Resultado esperado

Após a destruição da parede:

- A torre deveria invalidar o alvo antigo;
- Realizar um novo aggro search;
- Encontrar a Unit B como novo alvo;
- Atacar a posição atual da Unit B.

---

## Resultado atual

A torre continua atacando como se a Unit B estivesse na posição onde ela estaria caso a parede ainda existisse.

Exemplo:

Estado inicial:

```
Parede:
{0,0}
```

Após a parede ser destruída, a Unit B deveria estar em sua posição atual.

Porém a torre envia ataques para:

```
{0,1}
```

Que representa a posição onde a unit estaria caso ela estivesse atacando a parede.

Ou seja:

- a torre não está utilizando a posição atual da Unit B;
- está utilizando uma posição antiga/derivada do alvo anterior (a parede).

---

## Possível causa

Alguma informação relacionada ao alvo antigo está sendo mantida após a destruição da parede.

Possíveis cenários:

### 1. Ataque criado usando posição ao invés de referência da entidade

Exemplo:

```
AttackEvent
{
    attackerId,
    targetPosition
}
```

Nesse caso o ataque guarda apenas uma posição calculada anteriormente.

Quando o mundo muda, essa posição fica inválida.

---

### 2. Evento de ataque criado antes da destruição da parede

Exemplo:

```
T = 5.0

Torre encontra parede como alvo.

Cria AttackEvent:
{
    target = parede,
    position = {0,1}
}


T = 5.2

Unit destrói parede.


T = 5.5

AttackEvent é executado.
```

O evento ainda carrega informações antigas de quando a parede existia.

---

## Investigação

Verificar:

### Criação do ataque

Logar:

```
AttackCreated

attacker:
targetId:
targetPosition:
time:
```

Verificar se nesse momento o alvo já foi convertido em posição.

---

### Aplicação do ataque

Comparar:

```
AttackCreated

targetId:
targetPosition:
```

com:

```
AttackApplied

targetId:
targetPosition:
```

Verificar se o target original foi perdido.

---

### Destruição da parede

Quando a parede for destruída:

Verificar se ocorre invalidação de:

- currentTarget;
- aggroTarget;
- intents pendentes;
- eventos de ataque já criados.

---

## Hipótese principal

O sistema está mantendo uma referência antiga do alvo ou uma posição derivada do alvo antigo.

A torre deveria trabalhar com referência de entidade:

```
AttackEvent
{
    attackerId,
    targetId
}
```

e no momento da execução validar:

```
Target existe?
    |
    sim -> usa posição atual
    |
    não -> cancela ataque
```

O problema provavelmente está em algum ponto onde `targetId` é transformado em `targetPosition`.
